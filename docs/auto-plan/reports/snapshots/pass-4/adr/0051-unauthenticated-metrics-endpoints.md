# ADR 0051: Unauthenticated `/metrics` on Both the Main App and the Memory Service

**Status:** Accepted — 2026-06-08

**Context.** CLAUDE.md states the invariant "Bearer token auth on all endpoints except `/health`" — this applies to the **main app**, which enforces `BearerTokenMiddleware` (exempting `/health*`, `/metrics`, `/ui`, `/api/auth/token`). The main app's `/metrics` already ships unauthenticated via that exemption. The **memory service is a separate FastAPI app that today applies NO auth middleware at all** — every endpoint (including its `/admin/*` ops, gated only by the `MEMORY_ADMIN_ENABLED` env flag) is already unauthenticated. Prometheus scraping is simplest when the target requires no bearer token (Prometheus has no first-class bearer-auth in the basic scrape path). The memory service must add a `/metrics` endpoint too (ADR 0050).

**Decision.** Serve `/metrics` **unauthenticated on both services**. On the main app this is a deliberate second carve-out from the auth invariant alongside `/health` (it is already in the `BearerTokenMiddleware` exemption set). On the memory service it is consistent with that service's existing fully-unauthenticated posture (no carve-out needed). **Binding differs and the mitigation must not over-claim:** the main app binds loopback by default (`ServerConfig.host="127.0.0.1"`, reached via SSH tunnel). The **memory service binds `0.0.0.0`** (its Dockerfile/compose `command` pass `--host 0.0.0.0`; its `ServerConfig` has no `host` field), so under `network_mode: host` its `/metrics` is reachable on all host interfaces — the same exposure its existing endpoints already have. The compose-hosted Prometheus runs with `network_mode: host` and scrapes `localhost:8421/metrics` and `localhost:8422/metrics`. Metrics carry only low-cardinality counters/histograms (no content, no PII). `metrics.enabled=false` disables the endpoint on either service.

**Consequences / Alternatives.** Scrape config stays trivial and consistent with `/health`. For the main app the attack surface is bounded to loopback (single-user devgpu tool). For the memory service the metrics endpoint adds **no new exposure beyond what already exists** (the service is already `0.0.0.0`-bound and unauthenticated); the operative mitigation there is host-level network controls and the non-PII nature of the data — NOT loopback binding. We rejected bearer-protecting `/metrics` — it would force a token into Prometheus scrape config for marginal benefit. **Operational caveat:** because the memory service binds `0.0.0.0`, an operator who exposes the devgpu host beyond trusted network must front BOTH the memory service and the main app (if rebound off loopback) with network controls — noted as an operational caveat, not a code change in this work.

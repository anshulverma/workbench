# ADR 0021: Stable Source ID with Change-Detection Routing

Source adapters switch from compound `source_id` values that include volatile components (timestamps, update counters) to stable identifiers (`D{number}` for Phabricator diffs, `T{task_id}` for Meta Tasks). The scheduler's per-source poll job gains a post-poll routing step that uses `ItemStore.get_item_by_source_id(source_type, stable_id)` to split raw items into two paths: new items flow through `PipelineEngine.enqueue()` (unchanged), while existing items flow through a pluggable `ChangeDetector` interface that compares old vs new raw data and determines whether to re-triage, archive, or silently update.

We chose stable IDs over the previous compound format (`{number}_{updated}`) because the compound format treated every source update as a distinct item, creating duplicate `Item` rows and duplicate triage cards for the same diff or task. The stable ID collapses all updates into a single `Item` with in-place `raw_data` updates, enabling the `ChangeDetector` to diff old vs new state and selectively re-triage only on material changes.

We chose a pluggable `ChangeDetector` interface (one per source type, configured per source in YAML) over a generic diff-all-fields approach because materiality is source-type-specific: a new comment on a Phabricator diff is material, but a minor timestamp drift is not. We chose synchronous field comparison over LLM-based detection because the detector runs on every re-polled item (up to ~50 per source per poll cycle) and must be cheap.

The trade-off is a one-time re-ingestion: existing `processed` table rows have old compound keys that won't match new stable IDs, so already-ingested items get re-ingested once on the first poll after the migration. This is acceptable — the pipeline handles duplicates gracefully, and the ChangeDetector takes over dedup from that point forward.

**Consequence:** `SourceAdapter` gains two concrete methods: `supports_monitoring() -> bool` (default `False`) and `stable_id(raw_item) -> str` (default `raw_item.id`). New `ChangeDetector` ABC with `detect(old_raw, new_raw) -> ChangeResult`. New `AlwaysMaterialDetector` fallback. `_poll_one_source` refactored to route through `_route_poll_results`. New `ItemStore` method `get_item_by_source_id`. New indexes on `items(source_type, source_id)` and `triage_cards(item_id)`.

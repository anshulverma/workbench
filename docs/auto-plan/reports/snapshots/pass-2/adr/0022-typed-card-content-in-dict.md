# ADR 0022: Rich Card Content as Typed-Pydantic-in-Dict with a `content_schema` Discriminator

Rich, source-type-specific Triage Card content (for diffs: metadata, summary, risk, why-care, curated hunks) is stored as a typed pydantic model serialized **into** the existing untyped `TriageCard.card_content` dict column, under `card_content['sections']`, tagged by a `card_content['content_schema']` discriminator (e.g. `"diff.v1"`). Legacy `card_body` and `summary` keys are retained for the plain fallback path. The source-agnostic `DiffCardContent` model lives in the **foundational** repo (`src/workbench/models.py`) even though only the Meta diff path populates it, so the dashboard UI can statically type the detail view and a future source can reuse the shape.

We chose this over (a) new typed columns on `TriageCard` per source_type — which forces an Alembic migration every time a source plugs in, contradicting the source-pluggable goal and the user's "avoid future migrations" preference; (b) a fully untyped dict — no validation, brittle rendering; (c) a separate polymorphic `card_contents` table — over-engineered for a single-user tool. Typed-in-dict gives validation without schema churn.

**Consequence:** No migration is needed to ship this or to add future source content schemas. Presenters and the detail view `model_validate` their expected `content_schema`; on validation failure or absence they fall back to the plain path via `card_body`/`summary`. In-flight cards generated before this feature lack `sections` and render via `PlainCardPresenter` (forward-only, no data migration). The schema version (`diff.v1`) is bumped only when the section shape changes.

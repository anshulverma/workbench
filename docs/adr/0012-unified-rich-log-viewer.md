# ADR 0012: Unified Rich Log Viewer with JSON-on-Disk

Workbench logs were inconsistent and hard to read: the `workbench` app rendered uncolored `glog` lines with `"unknown"` source locations, while the `memory` service used a separate hand-rolled `GlogFormatter`. Operators read logs through `make logs` (`tail -f` over `data/logs/*.log`), so there was no color and no `file:line`.

We chose to make all coloring and layout decisions in a single **viewer** (`workbench/scripts/logview.py`, built on Rich) that tails every log file and renders a unified stream, while each Python service writes **plain JSON lines** to disk (Approach B). The viewer lives in `workbench` (not the Meta overlay) because it parses the JSON schema that `workbench`'s logging code defines and the log files live there — schema and viewer evolve together. It is generic: the only Meta-specific concern, hiding dcat noise, is expressed as `--exclude dcat` from the Meta repo's Makefile, not baked into the viewer. We rejected having each service write ANSI color into its own files (Approach A — postgres/neo4j physically cannot emit color, so logs would never be consistent) and a hybrid where Python files self-color and the viewer colors the rest (Approach C — two coloring mechanisms, fiddly, drifts out of sync).

The on-disk JSON schema — not shared code — is the consistency contract. `workbench` and `memory-service` are independent packages (ADR 0009) and must not import each other, so each independently configures structlog to emit the same fields, including `filename`/`lineno` via `CallsiteParameterAdder` (fixing the `"unknown"` location). Native services we don't control (postgres, neo4j) are tuned only enough for the viewer's regex parsers; a raw-text fallback parser guarantees no line is ever dropped.

Python services store timestamps as **UTC with a `Z` suffix** (`TimeStamper(utc=True)`); the viewer converts to `America/Los_Angeles` for display, so `make logs` still reads in Pacific. This resolves a latent defect: the containers run in UTC and the previous `utc=False` produced ambiguous naive strings, while `LoggingConfig.timezone` was never actually wired into the timestamper. Native services keep their own configured zone on disk; the viewer normalizes all of them to one display zone. Note that `neo4j-user-logs.xml` is Log4j2 (not logback) with separate file and console appenders — only the console appender is captured by the compose `tee`, so the parser-facing pattern is set there.

The trade-off: color is available only through the viewer (`make logs`), not a raw `cat` of a file. This is acceptable because operators already live in `make logs`, and plain JSON files stay grep- and editor-friendly and remain directly consumable by log aggregation. The `format` setting collapses to `json` (default, the contract) and `console` (opt-in for running a service attached to a TTY without the viewer).

**Consequence:** `GlogRenderer` is removed from `workbench/logging.py` and `GlogFormatter` from `memory/logging.py`; both gain `CallsiteParameterAdder`. `memory-service` adds a `structlog` dependency; the workbench repo adds a `rich` dependency used by the viewer (run via the host workbench venv). Both repos' `make logs` targets run `logview.py` instead of `tail` (the Meta one adds `--exclude dcat`). The structlog setup is duplicated across the two services by design — centralizing it is explicitly out of scope.

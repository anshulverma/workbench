# ADR 0013: Source and Messenger Config Write-Back to YAML with Targeted Hot-Reload

The Management Dashboard creates, edits, and deletes sources and edits the messenger by writing the change **back to the base `config.yml`** and **hot-reloading** the affected provider at runtime — no server restart. Writes use a `ruamel.yaml` round-trip that edits only the `sources:`/`messenger:` nodes, preserving `${oc.env:...}` interpolation strings, comments, and formatting, and are flushed atomically (temp file + `os.replace`). The runtime sequence is **validate → instantiate → write YAML → copy-on-write swap**, executed under a single `asyncio.Lock`; if instantiation fails, nothing is written. YAML remains the single source of truth; the disconnected `source_configs` table is deprecated as a config store. This reverses the CONTEXT.md "Dropped concepts" entries "POST/DELETE /api/sources — YAML-only" and "POST /api/reload — deferred (restart required)".

We chose write-back-to-YAML over a DB-backed source store (the earlier recommendation) because the user requires both durability in version-controlled config **and** immediate effect, and because YAML already carries `${oc.env}` secret references that a DB round-trip would either lose or resolve into plaintext. We chose targeted provider swap over a full `load_config` reload because a full reload re-resolves every interpolation and re-instantiates unrelated providers (LLM, storage, connections), a far larger blast radius than needed.

The trade-offs: we add a `ruamel.yaml` dependency and must never serialize the resolved OmegaConf container (which would bake secrets into the file); a source referencing a *new* connection cannot be hot-added (connections stay YAML + restart); and an active `WORKBENCH_CONFIG_OVERRIDE` can make the live merged view diverge from the base file we edit (UI writes target the base only).

**Consequence:** `connections`, `llm`, and `storage` changes still require a restart. Messenger swap must also update `scheduler.messenger` and `alert_manager.messenger`. `app.state.sources` is mutated copy-on-write so the scheduler poll loop never sees a list mutated mid-iteration. Secrets are never accepted from the browser nor written as resolved values.

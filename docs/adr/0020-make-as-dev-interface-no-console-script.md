# ADR 0020: Make is the Developer Interface; Remove the `workbench` Console Script

`make` is the single entrypoint for every developer action in workbench/ (setup, build, run, test, migrate, lint/format, UI build, triage). The `workbench` console script (`[project.scripts]` → `workbench.cli:main`, with `serve`/`triage` subcommands) is removed: `serve` becomes `python -m workbench` (a thin `__main__.py` launcher that loads config and runs uvicorn with `config.server.host`), and `triage` becomes `scripts/triage.py` invoked by `make triage`. `src/workbench/cli.py` is deleted.

We chose this because the console script and the Makefile already overlapped and drifted: `workbench serve` had **no runtime callers** (the container `entrypoint.sh` and the workbench-meta compose override both invoke `uvicorn` directly), while `workbench triage` was only ever called from `make triage`. A single Make interface removes the duplicate surface, keeps the loopback bind (ADR 0017) honored via `python -m workbench`, and stays aligned with workbench-meta, whose standalone Makefile drives the full stack and now launches the container via the same `python -m workbench` entrypoint.

The trade-off: developers lose a top-level `workbench` command on their PATH and must use `make <target>` (or `python -m workbench` / `scripts/triage.py` directly). For a single-user, repo-local tool that is an acceptable loss for one consistent, discoverable interface and no drift between the script and the Makefile.

**Consequence:** `pip install -e .` no longer installs a `workbench` binary. `config.server.host` is retained (the launcher reads it). README, CLAUDE.md, `console.py`'s triage hint, and ADR 0001's "`workbench triage` CLI" reference are updated to `make serve` / `make triage`. The base `Dockerfile` UI-copy path is corrected to `/app/ui/dist` (so the image serves `/ui`) and `make build` depends on `ui-build`. `ruff` is added (the `lint`/`format` targets). workbench-meta is updated in lockstep (host `ui-build` before `make up`; override command → `python -m workbench`).
